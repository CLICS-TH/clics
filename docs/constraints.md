# Key Constraints

- **On-premise mandate:** All PII and audit-trail data must remain on-premise. Only stripped JSON reaches cloud APIs. (As-built: PII stripping is regex-based — see [MIDDLEWARE-KNOWN-GAPS.md](MIDDLEWARE-KNOWN-GAPS.md).)
- **Provider randomization:** L4 selects the AI provider per session using `hashSessionId()`. One provider per CLE. `provider_used` is logged for audit. *(Planned — not yet implemented; runs Claude-only.)*
- **Pseudonymization:** Physicians mapped P-001…P-075; CLEs mapped CLE-001…CLE-150. Lookup table is encrypted and access-gated. *(Partially built: `professionals.pseudonym` (P-NNN) is now assigned at account creation/approval and is the only identifier allowed in exports/audit. OAuth real identities live encrypted in the `oauth_identities` vault — see below. Broader PII coverage + the bare-name leak are done (2026-06-18), and a **reversible on-prem PII map now exists**: at finalization the backend stores one AES-256-GCM-encrypted `[NAME-n]→raw` map per CLE in `cle_pii_map` (RLS deny-all, `IDENTITY_ENC_KEY`), decryptable only by the superadmin/PI via the gated, audit-logged `GET /admin/cles/:id/pii-map`. The export stays pseudonym-only.)*
- **Identity vault (OAuth):** When a user signs up via Google/LINE, their real identity (name/email/provider id) is AES-256-GCM-encrypted (app key `IDENTITY_ENC_KEY`) into `public.oauth_identities` on-premise. That table has RLS **deny-all** (only the backend's service-role key can read it) and is **never** queried by RIMPL. The mapping chain is `oauth_identities.identity_encrypted → professionals.id → professionals.pseudonym`; only the pseudonym is ever externally visible. The cloud AI layer receives none of it. **One PII-bearing field now crosses into RIMPL on-prem:** the physician's structured `patient_ref` (from `cle_patient_refs`) is passed on the chat + evaluate calls **solely so RIMPL can deterministically scrub those exact strings from the narrative** (closing the bare-unlabelled-name leak — see [MIDDLEWARE-KNOWN-GAPS.md](MIDDLEWARE-KNOWN-GAPS.md)); it is stripped before any cloud call and is **never** forwarded to the cloud AI.
- **Guest mode (ephemeral):** A guest has no `auth.users`/`professionals`/`cles`/`messages`/audit rows — ever. The only egress is the message text → RIMPL PII-strip → cloud AI, identical to a physician turn. The guest token is a short-lived HMAC blob (key `GUEST_TOKEN_SECRET`) carrying only a random session id; the 2-prompt cap is enforced by an in-memory TTL counter. Nothing is carried across sessions.
- **Reproducibility:** All CCME LLM evaluation runs tagged with model version (`CCME_LLM_v8.0`). If the model updates mid-study, re-evaluate the Tier-2 sample for drift. (The Claude model is pinned in `rimpl/src/services/claude.js`.)
- **ICC gate:** The Calibration Workshop must achieve ICC ≥ 0.75 before Tier-2 audit begins.

## Security

- Live credentials live **only** in gitignored `backend/.env` / `rimpl/.env` and platform env vars (Railway/Vercel dashboards) — never in committed files. `.claude/`, `*.rtf`, `*.env` are gitignored.
- `INTERNAL_TOKEN` is the shared secret between backend and RIMPL; it must match byte-for-byte on both services. RIMPL refuses to boot in production if it is unset.
- Anything sent to the manager (creds + URLs) must contain **zero** secrets.
