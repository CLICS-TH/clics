## 1. สรุปสำหรับผู้ตัดสินใจ

ขอติดตั้ง service ชื่อ **RIMPL** ซึ่งเป็นส่วนกลางของระบบ CLICS ลงบนเครื่อง `cme-dev`
หรือเครื่องอื่นที่อยู่ใน Tailscale เดียวกัน

| หัวข้อ | รายละเอียด |
|---|---|
| ประเภท | Node.js service ตัวเดียว ไม่มีฐานข้อมูลของตัวเอง ไม่เก็บไฟล์ |
| หน่วยความจำ | **75 MB** (วัดจากการรันจริง ขณะไม่มีงาน) |
| พื้นที่ดิสก์ | ประมาณ 250 MB รวม Node.js runtime และ dependencies |
| GPU | **ไม่ใช้เลย** ไม่โหลดโมเดล ไม่ใช้ CUDA ไม่แตะ vLLM หรือ Ollama ที่รันอยู่ |
| พอร์ตที่เปิด | TCP **3003** เฉพาะภายในเครือข่าย Tailscale เท่านั้น |
| พอร์ตที่ขอเปิดเพิ่มจาก firewall | **ไม่มี** |
| สิทธิ์ที่ต้องใช้ | ไม่ต้องใช้ root ถ้าติดตั้งด้วย Docker ใช้สิทธิ์ระดับผู้ใช้ทั่วไปพอ |
| ถอนออก | หยุด container แล้วลบทิ้ง ไม่มีอะไรตกค้างในระบบ |

**เหตุผลที่ขอติดตั้งบนเครื่อง แทนการยิงเข้ามาจากภายนอก**

ปัจจุบัน service นี้รันอยู่บนคลาวด์ และต้องยิงเข้ามาที่พอร์ต 3000 ของ `cme-dev`
ซึ่งถูกปิดกั้นอยู่ ถ้าย้าย service มาไว้บนเครื่อง มันจะคุยกับโมเดลผ่าน `localhost`
จึงไม่ต้องเปิดพอร์ตอะไรเพิ่มเลย และตรงกับที่ระเบียบ CREC082 กำหนดไว้ด้วย
ว่าการถอดข้อมูลระบุตัวตนต้องเกิดขึ้นในสถานพยาบาล

## 2. service นี้ทำอะไร

RIMPL คือชั้นกลางระหว่างระบบ CLICS กับโมเดล AI มีหน้าที่หลัก 2 อย่าง

1. **ถอดข้อมูลระบุตัวตนผู้ป่วยออก** ก่อนส่งข้อความไปให้โมเดล — ชื่อ, เลขบัตรประชาชน,
   เลข HN, เบอร์โทร, วันเดือนปีเกิด ถูกแทนที่ด้วยรหัสก่อนออกจาก service เสมอ
2. **ส่งต่อไปยังโมเดล** แล้วรับคะแนนกลับมา ตามเกณฑ์ PIS-7 ของโครงการ

มี 4 เส้นทาง (endpoint) คือ `/chat`, `/evaluate`, `/evaluate-criteria`, `/audit-discuss`
และอีก 2 เส้นทางสำหรับตรวจสุขภาพระบบคือ `/health` และ `/health/deep`

ทั้งหมดเป็น **stateless** — ไม่มีการเขียนไฟล์ ไม่มีฐานข้อมูลในเครื่อง
ข้อมูลผ่านเข้ามาในหน่วยความจำแล้วออกไป ไม่มีอะไรค้างบนดิสก์

## 3. สิ่งที่ service นี้ไม่ทำ

เขียนไว้ให้ชัด เพราะเป็นข้อกังวลที่สมเหตุสมผลของเจ้าของเครื่อง

- **ไม่แตะโมเดลหรือ Open WebUI ที่ใช้งานอยู่** ไม่แก้ config ไม่ restart ไม่โหลดโมเดลใหม่
- **ไม่ใช้ GPU** ทั้ง VRAM และ compute จึงไม่แย่งทรัพยากรกับงานที่รันอยู่
- **ไม่เปิดพอร์ตออกอินเทอร์เน็ต** พอร์ต 3003 มองเห็นได้เฉพาะเครื่องใน Tailscale
- **ไม่อ่านไฟล์อื่นในเครื่อง** ทำงานอยู่ใน container ของตัวเอง
- **ไม่ติดตั้ง agent เฝ้าระวังหรือเก็บ log ของเครื่อง**

## 4. เส้นทางข้อมูล — ขอเรียนตามตรง

ข้อนี้สำคัญที่สุด และขอไม่กล่าวเกินจริง มี 3 อย่างที่เป็นจริงพร้อมกัน

- **การเชื่อมต่อเข้ามาเข้ารหัสตลอดเส้นทาง** ผ่าน Tailscale (WireGuard) และต้องมี
  shared secret (`INTERNAL_TOKEN`) จึงจะเรียกได้ ไม่ใช่การเปิดรับจากอินเทอร์เน็ต
- **ข้อความบทสนทนาที่ยังไม่ถอดข้อมูลระบุตัวตนจะวิ่งเข้ามาที่เครื่องนี้** เพราะ RIMPL
  คือตัวที่ทำหน้าที่ถอด การถอดจึงต้องเกิดหลังจากข้อมูลมาถึงแล้ว
- **แต่นี่ไม่ใช่ความเสี่ยงประเภทใหม่** เพราะปัจจุบันฐานข้อมูลของโครงการอยู่ที่
  ap-northeast-1 (โตเกียว) อยู่แล้ว ข้อมูลจึงข้ามพรมแดนอยู่ก่อนหน้านี้

ดังนั้นสิ่งที่การย้ายครั้งนี้เปลี่ยน คือ **การส่งข้อมูลไปให้โมเดล AI** จะเกิดขึ้น
ภายในเครื่องนี้ และโมเดลจะได้รับเฉพาะข้อความที่ถอดข้อมูลระบุตัวตนแล้วเท่านั้น
ส่วนเรื่องที่เก็บฐานข้อมูลเป็นคนละประเด็นและยังไม่ได้แก้ในครั้งนี้ครับ

**ไม่ขอกล่าวว่า "ข้อมูลผู้ป่วยจะไม่ออกนอกประเทศ"** เพราะยังไม่จริงในตอนนี้

## 5. การเชื่อมต่อของ service

**ขาเข้า** — TCP 3003 จากเซิร์ฟเวอร์ของระบบ ผ่าน Tailscale เท่านั้น
ต้องแนบ shared secret ทุกครั้ง มิฉะนั้นถูกปฏิเสธ

**ขาออก** — HTTPS ไปยัง 2 ปลายทาง และ HTTP ภายในเครื่อง 1 ปลายทาง

| ปลายทาง | พอร์ต | ใช้ทำอะไร |
|---|---|---|
| `api.anthropic.com` | 443 | โมเดลคลาวด์ที่ใช้ให้คะแนนอยู่ในปัจจุบัน |
| ฐานข้อมูลโครงการ (Supabase) | 443 | อ่านการตั้งค่า และบันทึกผลคะแนน |
| `localhost:3000` (Open WebUI) | 3000 | เรียกโมเดล deepseek ในเครื่อง |

ถ้าเครื่องมีนโยบายจำกัด outbound รบกวนแจ้งครับ ผมปรับให้เข้ากับข้อกำหนดได้

## 6. ขั้นตอนติดตั้ง

### สิ่งที่รบกวนอาจารย์หรือผู้ดูแลเครื่องทำ (ประมาณ 5 นาที)

หลังจากนี้ผมทำเองทั้งหมดครับ

**1. สร้างบัญชีสำหรับระบบ**

```bash
sudo adduser clics
```

**2. ใส่ SSH public key ของผม** (เป็นกุญแจสาธารณะ ไม่ใช่ความลับ ผมสร้างขึ้นใหม่
เฉพาะงานนี้ จะได้ยกเลิกได้อิสระเมื่อจบโครงการ)

```bash
sudo mkdir -p /home/clics/.ssh
sudo tee /home/clics/.ssh/authorized_keys <<'KEY'
ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIEK4CzeojhgJWevnkBzXXpl3AjjzV7FFMMfYA96n8AoW clics-rimpl
KEY
sudo chown -R clics:clics /home/clics/.ssh
sudo chmod 700 /home/clics/.ssh
sudo chmod 600 /home/clics/.ssh/authorized_keys
```

**3. เฉพาะกรณีเลือกติดตั้งด้วย Docker** — เพิ่มบัญชีเข้า group

```bash
sudo usermod -aG docker clics
```

> **ขอเรียนตามตรงว่าคำสั่งข้อ 3 ให้สิทธิ์เทียบเท่า root ครับ** การอยู่ใน `docker`
> group ทำให้ mount อะไรเข้า container ก็ได้ จึงเข้าถึงทั้งเครื่องได้ ถ้าอาจารย์
> หรือผู้ดูแลไม่สะดวก **ข้ามข้อ 3 ไปได้เลย** แล้วใช้ "วิธีที่ 2" ข้างล่าง
> ซึ่งรันด้วย Node.js ตรง ๆ ไม่ต้องใช้ Docker และไม่ต้องเข้า group ใด ๆ
> ต้องการเพียง `sudo` ครั้งเดียวตอนวางไฟล์ systemd หรือจะให้ผู้ดูแลเป็นคนวางให้ก็ได้ครับ

**4. แจ้งกลับมาว่า** ชื่อบัญชีคืออะไร และเครื่องมี Docker ติดตั้งไว้หรือไม่

**สิทธิ์ที่ผมจะได้รับ:** เข้าใช้งานได้ในระดับผู้ใช้ทั่วไปของบัญชี `clics` บัญชีเดียว
เท่านั้น ไม่ใช่ root และไม่ใช่บัญชีของผู้อื่น เข้าได้เฉพาะจากเครื่องที่ถือกุญแจส่วนตัว
คู่กันซึ่งอยู่บนโน้ตบุ๊กผมเครื่องเดียว และเฉพาะผ่านเครือข่าย Tailscale เท่านั้น
อาจารย์ยกเลิกสิทธิ์ได้ทุกเมื่อโดยลบบรรทัดกุญแจออกจากไฟล์ `authorized_keys`
ผมจะเข้าไปทำเฉพาะสิ่งที่เกี่ยวกับ service นี้ ไม่ยุ่งกับงานหรือข้อมูลส่วนอื่นในเครื่องครับ

### วิธีที่ 1 — Docker (แนะนำ)

ซอร์สโค้ดอยู่ใน repository แบบปิด ผมจึงเป็นผู้นำไปติดตั้งให้ครับ
(หรือถ้าอาจารย์ประสงค์จะตรวจก่อน ผมเปิดสิทธิ์อ่านให้ได้ทันที — ดูข้อ 9)

```bash
# 1. สร้าง image จากซอร์สที่ผมนำไปวางไว้ (ใช้เวลาประมาณ 2 นาที)
cd clics/rimpl
docker build -t clics-rimpl .

# 2. ใส่ค่าตั้งต้น
cp .env.example .env
$EDITOR .env
chmod 600 .env

# 3. รัน
docker run -d --name clics-rimpl --restart unless-stopped \
  --network host --env-file .env clics-rimpl
```

ไฟล์ `.env` **ไม่มีข้อมูลผู้ป่วย** แต่มีกุญแจเข้าถึงบริการของโครงการอยู่
จึงตั้งสิทธิ์เป็น `600` ไว้ครับ ผมเป็นผู้เตรียมค่าในไฟล์นี้ให้ทั้งหมด

ใช้ `--network host` เพื่อให้ service เห็นทั้งพอร์ต 3000 ในเครื่อง
และรับการเชื่อมต่อผ่าน Tailscale ได้ ถ้าทางเครื่องไม่อนุญาต `--network host`
ใช้ `-p 3003:3003` แทนได้ครับ แต่ต้องระบุที่อยู่ของ Open WebUI ให้ชัดเจนแทน `localhost`

### วิธีที่ 2 — รันด้วย Node.js โดยตรง

ถ้าไม่สะดวกใช้ Docker ต้องมี **Node.js เวอร์ชัน 22 ขึ้นไป**

```bash
cd clics/rimpl
npm ci --omit=dev
node src/index.js
```

(`npm ci` ดึง dependency 6 ตัวจาก npm registry — ต้องต่ออินเทอร์เน็ตได้ในขั้นตอนนี้
ถ้าเครื่องออกเน็ตไม่ได้ ผมเตรียม image สำเร็จรูปไปให้แทนได้ครับ)

แนะนำให้ทำเป็น systemd service เพื่อให้รันต่อหลังเครื่อง reboot
ผมจัดทำ unit file ให้ได้ครับ

## 9. ความปลอดภัย

- **ต้องมี shared secret จึงเรียกได้** ทุก endpoint ยกเว้น `/health` ถูกป้องกันด้วย
  `INTERNAL_TOKEN` และ service จะ **ปฏิเสธที่จะเริ่มทำงาน** ถ้าไม่ได้ตั้งค่านี้ในโหมด production
  เป็นการออกแบบให้พังดังกว่าเปิดโล่งเงียบ ๆ
- **มองเห็นได้เฉพาะใน Tailscale** ไม่มีการเปิดพอร์ตออกอินเทอร์เน็ต
- **ยินดีให้ตรวจซอร์สโค้ดทั้งหมด** repository เป็นแบบปิด แต่ผมเปิดสิทธิ์อ่านให้อาจารย์
  หรือผู้ดูแลเครื่องได้ทันทีที่แจ้งมาครับ (แจ้งชื่อบัญชี GitHub มาได้เลย)
  หรือจะให้ส่งเป็นไฟล์ให้ตรวจก่อนก็ได้ครับ
  ส่วนที่ถอดข้อมูลระบุตัวตนอยู่ที่ `rimpl/src/services/pii-filter.js`
  และมีชุดทดสอบเฉพาะทางที่จงใจพยายามทำให้ข้อมูลรั่วเพื่อพิสูจน์ว่ากันได้จริง อยู่ที่
  `rimpl/tests/pii-leak-adversarial.test.js`
- **dependencies มีเพียง 6 ตัว** ทั้งหมดเป็นไลบรารีมาตรฐาน ได้แก่ express, zod, undici,
  dotenv, Supabase client และ Anthropic SDK
- **image ตรึงเวอร์ชัน** ทั้ง Node.js และ Tailscale client ระบุเวอร์ชันชัดเจน
  ไม่ใช้ `latest` เพื่อให้ตรวจสอบย้อนหลังได้ว่าในเครื่องมีอะไรอยู่

## 10. หากไม่สะดวก

ถ้าอาจารย์เห็นว่าการติดตั้งบนเครื่องไม่เหมาะสม ยังมีทางเลือกอื่นครับ

1. ติดตั้งบนเครื่องอื่น — ได้ผลเหมือนกันครับ แต่เครื่องนั้นต้องเข้าสองอย่างได้
   คือเรียก Open WebUI ได้ (ผ่าน LAN) **และอยู่ใน Tailscale ด้วย** เพราะปัจจุบัน
   `cme-dev` ไม่ได้ประกาศเส้นทางไปยังเครื่องอื่นในวง LAN (ไม่มี subnet route)
   ระบบภายนอกจึงมองเห็นเฉพาะ `cme-dev` เครื่องเดียว
2. ผมจัดหาเครื่องขนาดเล็กมาวางในวง LAN เอง โดยไม่รบกวนเครื่องของอาจารย์
   (เครื่องนั้นผมจะให้เข้า Tailscale ด้วย ตามเงื่อนไขข้อ 1)
